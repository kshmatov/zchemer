# Цель проекта

Проект в игровой форме учит языку Scheme программистов, ранее не работавших со Scheme. Игра — соло, нативное десктоп-приложение (без Electron/браузера). Сначала изучается база языка (синтаксис, рекурсия, замыкания), затем игрок выбирает из нескольких продвинутых треков:
- интерпретатор Scheme (в MVP)
- многозадачность (в MVP)
- работа с сетью (TCP, UDP, HTTP) — планируется, вне MVP
- работа с базами данных — планируется, вне MVP
- объектно-ориентированное программирование и другие подходы — планируется, вне MVP

Все темы можно проходить в желаемом порядке; пересекающиеся навыки описаны явным графом пререквизитов и учитываются при разблокировке последующих тем.

Стек: Racket (`racket/gui` для нативного GUI, `racket/sandbox` для безопасного запуска кода игрока).
Scheme примем в стандарте R6RS.

GUI должен предоставлять возможность писать код непосредственно в нём для простых примеров (свой редактор на `text%`/`editor-canvas%`) и загружать более сложные проекты при необходимости (выбор папки с `.scm`-файлами).

Обучающая информация выводится текстом в формате бортжурнала/записей от первого лица, без диалогов между персонажами и без сюжетных миссий.

Прогресс игрока (звания/уровни, достижения, состояние по трекам) хранится локально в человекочитаемом файле (JSON/S-expression) рядом с приложением.

Проект должен включать в себя интерпретатор языка для проверки кода игрока: статический анализ + автотесты, ошибки переводятся в обучающие LCARS-стилизованные подсказки.

Внешний вид стилизовать под интерфейс StarTrek Voyager/New Generation (LCARS) — только визуальный стиль, без сюжетного обрамления и ролей учителя/класса.

Развёрнутая спецификация: `openspec/specs/` (`curriculum`, `game-progression`, `scheme-runtime`, `code-evaluation`, `advanced-project-sandboxes`, `gui-lcars`, `progress-persistence`); архитектурные решения и альтернативы — `openspec/changes/archive/2026-09-06-define-project-scope/design.md`.
