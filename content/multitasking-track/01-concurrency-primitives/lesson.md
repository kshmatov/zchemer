## Log Entry

Личный журнал. Сегодня впервые запустила два потока одновременно на одном и том же корабельном счётчике — и получила разные итоговые значения при разных запусках одной и той же программы. Никакой ошибки в коде не было: оба потока читали и писали общий счётчик без какой-либо координации, и порядок, в котором это происходило, каждый раз оказывался разным. `thread` запускает процедуру параллельно, по-настоящему, а не по расписанию, которое я могла бы предсказать.

Чтобы вернуть предсказуемость там, где она нужна, есть `semaphore`: `semaphore-wait` и `semaphore-post` образуют пропускной пункт вокруг общего ресурса — только один поток проходит между ними одновременно, остальные ждут своей очереди. `channel` — ещё один инструмент: способ, которым потоки передают друг другу значения напрямую, без общей переменной вообще. Здесь пока хватит семафора: он превращает «два потока портят один счётчик» в «два потока по очереди безопасно его увеличивают».

## Exercise

Определите процедуру `(synchronized-sum n)`, которая:
1. заводит общий счётчик, начинающийся с 0, и семафор для защиты доступа к нему;
2. запускает (`thread`) две одинаковые параллельные задачи, каждая из которых `n` раз увеличивает счётчик на 1, используя семафор так, чтобы одновременно счётчик изменял только один поток;
3. дожидается завершения обоих потоков (например, через `thread-wait`);
4. возвращает итоговое значение счётчика.

Реализуйте увеличение рекурсией (без `for`/`when` — только конструкции, уже изученные в базовом курсе: `if`, внутренний `define`, `set!`). Независимо от того, в каком порядке потоки чередуются, результат должен всегда быть равен `(* 2 n)`.

Затем определите `(ping-pong n)`, которая создаёт канал (`make-channel`), запускает один поток-отправитель, последовательно передающий в канал числа от `1` до `n` (`channel-put`), а сама (в основном потоке) принимает их по одному (`channel-get`), суммирует и возвращает итоговую сумму — дождавшись завершения потока-отправителя.
