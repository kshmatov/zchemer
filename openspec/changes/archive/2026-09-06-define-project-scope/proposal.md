## Why

Проект zchemer описан пока только на уровне намерения (`AGENTS.md`): обучающая игра по Scheme со свободным порядком продвинутых тем, стилизованная под LCARS. Ключевые решения — стек, архитектура интерпретатора, устройство игрового слоя, песочниц для продвинутых тем и GUI — не зафиксированы. Без этого нельзя ни проектировать архитектуру, ни начинать реализацию. Цель этого change — пройти по согласованному списку открытых вопросов и зафиксировать результат в виде развёрнутой спецификации проекта (specs + design), которая станет основанием для последующих change'ей с реализацией.

## What Changes

- Формируется базовый набор capability-спек, описывающих поведение системы: учебный план, игровой слой прогресса, исполнение и проверка Scheme-кода игрока, песочницы для продвинутых треков, LCARS-интерфейс, сохранение прогресса.
- Фиксируются архитектурные решения (стек, способ исполнения Scheme-кода, устройство песочниц) в `design.md`.
- Определяется объём MVP и явные non-goals для первой итерации.
- Код не пишется — это change только на уровне спецификации и дизайна.

## Capabilities

### New Capabilities
- `curriculum`: структура учебного плана — базовый курс языка, продвинутые треки, зависимости между навыками, порядок прохождения.
- `game-progression`: игровой слой поверх учебного плана — сюжет/обрамление, звания и достижения, разблокировка тем, подача обучающего текста.
- `scheme-runtime`: встроенный интерпретатор Scheme (R6RS), исполняющий и проверяющий код игрока, включая песочницу выполнения (лимиты, изоляция).
- `code-evaluation`: проверка решений игрока и обратная связь (что считается правильным ответом, какие подсказки и сообщения об ошибках показываются).
- `advanced-project-sandboxes`: среды для продвинутых треков (сеть, БД, многозадачность, ООП и др.) — реальные сервисы или имитация, формат загрузки более сложных проектов.
- `gui-lcars`: интерфейс в стиле LCARS — редактор кода для простых примеров, экран для загруженных проектов, общая навигация.
- `progress-persistence`: сохранение и восстановление прогресса игрока между сессиями.

### Modified Capabilities
(нет — проект стартует с нуля, изменяемых спек ещё не существует)

## Impact

- Затрагивает: весь будущий код проекта (сейчас код отсутствует) — этот change определяет его границы.
- Выбор стека и архитектуры интерпретатора закладывает ограничения для всех последующих change'ей.
- Результат используется как источник истины при декомпозиции работ в `tasks.md` будущих реализационных change'ей.
